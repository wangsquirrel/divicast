# 已知问题与验证边界

本轮符号、干支、四柱及构造完整性重构保持既有排盘公式和有效输入的输出。
以下问题在重构前已经存在，尚未在本轮修复。修正规则时需要补充独立的领域案例，
明确预期结果，并审查由此产生的输出基线变化。

## 已确认的问题

| 位置 | 问题及影响 |
| --- | --- |
| `birth_chart/analysis.py::_element_that_restrains` | 当前按 `(target.num + 2) % 5` 返回“我克”的五行，却用于“克我”的官杀关系。例如木得到土而非金，会影响喜忌分析。 |
| `sixline/divinatory_symbol.py` 的华盖表 | 巳、酉、丑日支对应值写为酉，与同处注释中的丑不符，会影响六爻神煞输出。 |
| `birth_chart/geju.py::_is_gou_chen_de_wei` | 当前判断要求戊干配丑、未支，这些不属于六十甲子，合法命盘无法命中该分支。原来的非法测试输入已改为构造拒绝测试，格局规则仍待依据明确的领域口径修正。 |
| `birth_chart/birth.py::BirthChart.__init__` | 起运计算仍临时替换 `lunar.LunarHour.provider`。虽然会在 `finally` 中恢复，不同规则的并发调用仍可能互相干扰。共享四柱函数不依赖此全局状态。 |
| 八字 `calc_rules` 的保存、校验与输出 | 非空规则字典仍保留调用方引用，规则校验分散，部分未实际支持的口径可能进入输出元数据。应统一规则对象和验证，并保证元数据反映实际算法。 |
| `birth_chart/analysis.py` 的干支关系分析 | 部分相合模式命中后直接输出“化”的结果，尚未完整判断成化条件。面向 AI 的输出需要明确区分相合关系与成化结论。 |

## 后续结构改进

- 六爻对象仍有依赖分阶段装配的状态；本轮只完成 `ZhuInfo` 和 `BirthChart` 的构造完整性。
- 藏干对象及部分符号上的列表仍可修改，需要另行评估共享可变状态与不可变接口。
- 严格静态类型检查目前只覆盖本轮基础抽象和协议消费示例，尚未覆盖全库。

## 回归验证的含义

本轮对固定时间下的全部 4,096 种六爻输入，以及 72 个八字案例的两种子时规则，
共 4,240 份完整输出与重构前结果进行了逐项比较，结果一致。
这些检查说明所覆盖案例的输出保持稳定，不表示历史领域规则本身已经正确。
